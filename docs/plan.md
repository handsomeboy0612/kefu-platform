# 客服考核数据平台（kefu-platform）方案

> 状态：方案已确认（2026-11-24），开始一期。
> 替代客服评分系统（Performance-Rating）的两个桌面版；Performance-Rating 项目保留不再改动。

## 1. 为什么做

现在客服部和技术支持部各装一个桌面版评分系统，各存各的数据。这几天遇到的问题都出在这里：

- 每台电脑各存一份数据，结果可能不一样；本地数据曾从 639 段会话变成 2 段。
- 要有人手动点「同步」才有数据；每次改动都要重新打包、到每台电脑覆盖安装。
- 对公群要接 AI 分问题，放在哪台桌面电脑上跑都不合适。
- 时区、配置每台电脑都可能不一样（之前 UTC-5 时区导致数据错开 13 小时）。

改成内网网页平台后：**一份数据、自动同步、AI 在服务端跑一次、浏览器打开就用、改一次所有人生效**。

## 2. 已经定下来的

| 项 | 决定 |
|---|---|
| 形式 | 内网网页，新项目 kefu-platform；Performance-Rating 不再改 |
| 部署 | DESKTOP-81HRUPD（和归档服务、MySQL 放一起），浏览器访问 `http://DESKTOP-81HRUPD:8092` |
| 使用者 | 只给主管 / 管理员；客服部主管 钟孟玲、技术支持部主管 王智，另有一个总管理员 |
| 部门 | 两个部门在同一个平台里分开：各自的成员、数据源、考核规则，登录后只看自己部门 |
| 数据源 | SaleSmartly（两个部门共用同一个项目 g1qnrj2）+ 对公群（只给技术支持部） |
| 不做 | 企微存档（BitBrowser 取 Cookie），两个部门都不用了 |
| 历史数据 | 不导入，从平台上线起开始；SaleSmartly 会话可按需重新拉取历史时段 |
| 成员归属 | 一个人只属于一个部门 |
| 考核规则初始值 | 两个部门都用默认规则（客服部 = main 分支默认规则，技术支持部 = 技术支持部绩效考核标准默认规则） |
| 日报推送 | 暂不做 |
| 代码仓库 | 先建在周丛杰个人 GitHub 账号下，私有仓库 kefu-platform |

## 3. 整体结构

```
云雾机器人 / Relayrouter 机器人 ──► 归档服务 archive-server（:8091，不变）──► MySQL wecom_archive
                                                                            ▲
SaleSmartly 接口 ◄──────────────── 数据平台 kefu-platform（:8092，新）────────┤
                                     · 定时同步、AI 质检、AI 分问题、算绩效     │
                                     · 网页（主管用浏览器打开）               └──► MySQL kefu_platform（新库）
```

- **机器人、归档服务不动**。平台从归档服务的接口拉对公群消息，和现在桌面版的方式一样。
- 新建一个数据库 `kefu_platform`，放在同一个 MySQL 里，加进每天的自动备份。
- 资源占用：平台常驻约 100～200 MB 内存，平均 CPU 不到 1%（AI 在远端接口上算）。

## 4. 部门怎么分

| | 客服部 | 技术支持部 |
|---|---|---|
| 主管账号 | 钟孟玲 | 王智 |
| 成员 | 白班 / 晚班 / 通宵班客服 | 技术支持 |
| 数据源 | SaleSmartly | SaleSmartly + 对公群 |
| 考核规则 | 五项：接待量、回复率、满意度、响应速度、AI 质量（含通宵班专用规则） | 第一项「客服接待」+ 第二项「对公群」+ 主管评分（含投诉、表扬、扣分人工录入） |
| 菜单 | 没有「对公群」相关的页面和设置 | 有 |

- **成员归属**：成员表里由管理员给每个人指定部门。默认按 SaleSmartly 分组给出建议（白班 / 晚班 / 通宵班客服 → 客服部，技术支持 → 技术支持部），可以改。商务等不属于任何部门的人不参与考核。
- **共用一份底层数据**：SaleSmartly 只拉一次，每段会话按接待的人归到他所在的部门；对公群数据只有技术支持部用。
- **各改各的**：两个部门的考核规则、AI 质检提示词、绩效快照、人工录入、剔除记录互不影响。

## 5. 账号和权限

| 角色 | 能看 / 能改 |
|---|---|
| 总管理员 | 所有部门；系统设置（SaleSmartly Token、AI 接口、归档服务地址）、账号管理、成员分部门 |
| 部门主管（钟孟玲 / 王智） | 只看自己部门：会话记录、看板、绩效；改自己部门的考核规则、成员的班次和参与考核、AI 提示词、人工录入；技术支持部还能管对公群的群筛选和员工挂靠 |

- 用户名 + 密码登录，密码加密存储，只在内网访问。
- **记录操作日志**：谁在什么时候改了规则、剔除了哪条差评、改了哪个挂靠，考核有争议时能查。

## 6. 功能清单

基本照搬现有桌面版（技术支持部的分支是客服部 main 的超集，以它为主体，客服部的考核规则从 main 搬过来）：

| 页面 | 内容 |
|---|---|
| 会话记录 | 按日期、接待客服（可输入搜索）、渠道、评级、AI 评分状态、客户评价筛选；查看聊天记录；单条 / 批量 AI 评分；点击客户名复制 |
| 统计看板 | 与现在一致 |
| 绩效考核 | 按考核时段计算；两套规则；回复率扣分剔除、差评剔除；主管评分与投诉录入（技术支持部）；绩效快照；导出 |
| 对公群（技术支持部） | 群会话列表；同步结果里的漏挂提醒、采集中断提示；群筛选、切段间隔、群内员工挂靠 |
| 设置 | 系统设置（总管理员）；部门设置：成员与班次、参与考核、考核规则、AI 提示词 |
| 同步状态 | 每次自动同步的时间、结果、错误；可手动「立即同步」某个时段 |

现有已做好的逻辑都带过来：群昵称挂靠 + 包含匹配、派单规则、只认「参与考核」勾选、AI 测试连接校验模型、AI 评级标签写回 SaleSmartly。

**去掉的**：企微存档（BitBrowser）、桌面端的本地备份对话框（改成服务端每天自动备份）、「同步前清空」这类危险的本地操作。

## 7. 定时任务

| 时间 | 做什么 |
|---|---|
| 每小时 | 拉 SaleSmartly 当天和前一天已结束的会话，补拉聊天记录；拉对公群消息 |
| 每晚 01:00 | AI 质检没评过分的会话；AI 分问题（前一天定稿，二期）；评级标签写回 SaleSmartly |
| ~~每天 09:00~~ | ~~日报推送到企业微信群~~（暂不做） |

- SaleSmartly 接口限速每秒 20 次（账号级），平台沿用现有的限速控制。每天约 270 段会话，一次同步几分钟内完成。
- 时间一律按北京时间，服务端写死，不依赖电脑的时区设置。

## 8. 数据表（MySQL 库 kefu_platform）

| 表 | 内容 |
|---|---|
| departments | 部门（客服部、技术支持部），各自的考核规则、AI 提示词 |
| accounts | 登录账号、角色、所属部门 |
| members | SaleSmartly 成员缓存 + 所属部门、班次、是否参与考核 |
| sessions / messages | 会话和聊天记录（SaleSmartly、对公群两个来源） |

| group_issues | AI 分问题结果（二期） |
| wecom_mapping | 群内员工 → SaleSmartly 成员挂靠 |
| exemptions | 回复率扣分剔除、差评剔除 |
| kpi_manual / kpi_snapshots | 人工录入、绩效快照 |
| sync_runs | 每次同步的记录 |
| audit_logs | 操作日志 |
| settings | 系统设置 |

## 9. 技术选型

- 服务端：Node + TypeScript（和现有评分系统同一种语言，业务逻辑可以直接搬）。
- 网页：React + Vite + Semi UI（现有页面基本照搬，把 57 个桌面端内部调用换成网页接口）。
- 部署：和归档服务一样，用 Windows 计划任务开机自启，崩溃后自动重启。

## 10. 分几期做

| 期 | 内容 | 上线方式 |
|---|---|---|
| 一期：搬家 | 账号和部门、SaleSmartly 同步、会话记录、AI 质检、看板、两套绩效规则、对公群（沿用现有规则拆段）、定时同步、同步状态页 | 和桌面版并行；两个部门对照一个考核周期，数据一致后停用桌面版 |
| 二期：AI 分问题 | 按 [ai-issue-plan.md](ai-issue-plan.md) 做；处理时效、问题闭环率开始计分 | 先影子模式，人工核对达标后再计分 |
| 三期 | 操作日志查询页等（日报推送暂不做） | — |

## 11. 注意事项

- **DESKTOP-81HRUPD 要开着**：它现在就已经因为归档服务需要一直开着。关机期间网页打不开、掉线提醒发不出，但数据不会丢，开机后定时任务会补上。
- **并行期间的冲突**：桌面版和平台共用 SaleSmartly 的限速额度，避免同时大批量同步；AI 评级标签写回 SaleSmartly 在并行期间**只开一边**（建议平台先关掉），否则会重复写。
- **数据外发**：AI 质检和 AI 分问题会把聊天内容发给配置的 AI 接口，和现在一样。
